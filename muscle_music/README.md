# 肌律：IMU 手势实时生成音乐系统

肌律把手部挥动变成一首逐步形成的电子音乐。当前手环以 200 Hz 采集三轴加速度和三轴角速度，可以用于判断前、后、左、右、上、下六个方向，并估计动作强弱。第一版不把单个 IMU 无法可靠测出的捏合、握力、肌肉发力或三维位置写进功能范围。

系统生成新的乐句，不播放事先录好的音乐片段。六个方向分别控制鼓、环境纹理、和弦、主旋律、琶音和贝斯。首次进入某个方向会建立对应声部，离开后继续循环。再次进入同一方向时，系统沿原有主题增加节奏变化、装饰音、八度变化和问答句。动作强弱会影响力度、明亮度和节奏密度。

音乐始终处在统一调性、四小节和声与固定节拍中。旋律在强拍回到和弦音，和弦使用就近转位，贝斯主要采用根音和五度，各声部使用不同音域。六轨同时播放时，自动混音会降低容易拥挤的声部，并在底鼓出现时短暂压低贝斯、和弦和环境轨。总线上的混响、延迟、压缩和限幅用于统一空间感并控制峰值。

## 立即试听浏览器 Demo

首个可听版本不要求安装 Ableton 或虚拟 MIDI。它已经内置六条浏览器音色轨和一套可调混音台。运行：

```powershell
cd muscle_music
py .\serve_demo.py
```

在浏览器打开 `http://127.0.0.1:8765`。程序同时监听后端保留的 `127.0.0.1:9000` OSC 端口，并把 `/emgimu/state` 数据转给页面。点击“开始演奏”启用声音，再挥动手环逐层加入音乐。没有手环数据时，可以点击六个方向或用 `W/S/A/D/R/F` 测试；`J` 控制开始和结束，“自动演示一遍”可快速试听完整编曲。

主页面是一块实时生成画布。鼓点显示为向外扩散的圆环，环境声形成缓慢移动的色雾，和弦是成组的波纹，旋律是一条带音符节点的曲线，琶音以向上运动的光点表示，贝斯则形成底部宽波。再次进入同一方向时，画面和音乐会一起变得更复杂。连接信息、识别数值和六轨混音台收在默认关闭的“声音与设备设置”中，现场观众不需要阅读这些参数。

## 演示时用户怎样操作

一次体验建议控制在 60 至 90 秒。用户先点击“开始演奏”，看到一拍倒计时后，依次向不同方向挥动手环。每次确认一个新方向，页面会立即显示反馈，对应乐句会在下一拍或下一小节进入。已加入的声部会持续循环，所以几次简单挥动就能逐步形成一首完整编曲。

再次挥向同一方向时，对应声部会沿原主题继续发展。较轻和较有力的挥动会得到不同的力度、亮度和节奏密度。体验结束时点击“结束作品”即可停止声音；下一次开始会建立新的调性、和声和随机种子。

TouchDesigner 画面建议使用六个围绕中心的声部环。手势一经确认，对应区域立即点亮；实际乐句在小节边界进入。节拍环显示还需等待多久，避免观众把音乐量化造成的等待误认为系统没有响应。

画面同时显示本次作品的动作风格摘要，以及动态、连奏、已加入声部和复杂度。数值来自本次动作的累计统计。

## 当前完成内容

当前浏览器原型已经包含 9000 端口 OSC 转发、200 Hz 纯 IMU 状态说明、120 毫秒手势稳定确认、无需经过无动作的直接切换、六声部约束式音乐生成、四级主题演化、基于动作强度的会话变化、六轨混音台、自动平衡、输出电平显示、键盘模拟和无设备自动演示。

方向识别本身不在当前阶段实现。后端只需按照 `docs/PROTOCOL.md` 向 9000 端口发送数据，不需要修改页面和音乐部分。

## 安装

要求 Windows 10/11、Python 3.10 或更高版本、Ableton Live 12，以及一个虚拟 MIDI 端口。推荐使用 loopMIDI 建立名为 `JILV OUT` 的端口。

```powershell
cd muscle_music
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
jilv-list-midi
```

先按 `docs/ABLETON_SETUP.md` 配置六条 MIDI 轨道。之后启动音乐引擎：

```powershell
jilv-engine --midi-port "JILV OUT"
```

在另一个终端启动键盘模拟器：

```powershell
jilv-simulator
```

暂时没有 Ableton 或 loopMIDI 时，可以先运行无设备模式：

```powershell
jilv-engine --dry-run --no-visual --seed 42
jilv-simulator --demo
```

## 键盘模拟

浏览器页面中，`W/S/A/D/R/F` 对应前、后、左、右、上、下，`J` 控制开始和结束。页面没有收到手环数据时，可以用“运动强度”滑块模拟动作快慢。独立的 `jilv-simulator` 仍保留旧版九状态协议，主要用于测试完整 MIDI 引擎的兼容性。

## 测试

测试不需要安装 MIDI 依赖，也不需要连接 Ableton：

```powershell
$env:PYTHONPATH = (Resolve-Path '.\src')
py -m unittest discover -s .\tests -v
```

现有测试覆盖 OSC 编解码、连续状态切换、100 组以上的乐句约束检查、个性化差异、复杂度上限、小节量化、作品开始和结束、自动建立下一作品，以及保留手势不会误触发功能。

安装依赖后，可以先导出两份 MIDI，在 Ableton 中盲听个性化差异：

```powershell
jilv-preview --output soft.mid --motion 0.2 --muscle 0.2 --hold-ms 1100 --generation 2
jilv-preview --output energetic.mid --motion 0.9 --muscle 0.9 --hold-ms 250 --generation 2
```

两条命令使用相同种子和相同和声，因此差异主要来自演奏参数，而不是换了一首完全无关的随机作品。
